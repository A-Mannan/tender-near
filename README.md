# Tender

**A sealed-bid clearinghouse for AI labor — and the first public price index of what agents actually cost.**

Tender lets a buyer post an escrowed job on NEAR, lets worker agents submit sealed bids, clears the auction with a Vickrey second-price (or first-price) reverse auction, and prints the settled result to a public, receipt-backed market tape called **The Tape**. Every price on The Tape is derived from a real on-chain `job_settled` event — no mock numbers, no synthetic volume.

Built for **NEAR HACKATHON 2026** in the **Agents that Work** track, with secondary relevance to **business** (procurement) and **security** (sealed bids, escrow, payout rollback).

## The problem

Autonomous agents already buy and sell work — audits, labeling, code generation, research — but AI labor has no public clearing price:

- **Open order books leak quotes.** Competing bots undercut by 1 yoctoNEAR without revealing their true marginal cost.
- **Private API negotiations leave buyers blind.** There is no equivalent of FINRA TRACE or a CME tape for agent work.
- **Naive reverse auctions are not truthful.** Lowest-price-wins-with-last-price-payment rewards bid shading, so the printed price is not the real cost.

Tender separates the two concerns: **sealed bids** discover the price without leaking intent, and **The Tape** publishes only settled, receipt-anchored outcomes.

## How a job clears

1. **Escrow** — the buyer posts `create_job` with a reserve price, buyer-declared `work_units` + `unit_label`, SHA-256 spec hash, mechanism, and phase durations. The buyer's NEAR (or NEP-141) escrow is attached with measured storage deposit.
2. **Commit** — worker agents submit `commit_bid` with a domain-separated SHA-256 commitment. The bid amount, ETA, and salt stay private. No NEAR is attached, so a restricted `FunctionCall` access key is sufficient.
3. **Reveal** — after the commit deadline, workers call `reveal_bid` with the exact preimage. Mismatches, late reveals, and reserve violations are rejected.
4. **Clear** — `finalize_auction` picks the lowest valid bid. In Vickrey mode the clearing price is `min(runner_up_bid, reserve_price)`; with a single reveal, the reserve acts as the virtual runner-up. First-price jobs clear at the winning bid. Ties break by earliest commit sequence.
5. **Deliver & settle** — the winner submits a deliverable URI + SHA-256. The buyer accepts, or anyone can call `finalize_after_timeout` after the dispute window so a silent buyer cannot hold escrow hostage. Settlement emits the `job_settled` NEP-297 event that becomes a Tape print.

```
buyer ──create_job(escrow)──▶ Tender contract ◀──commit_bid(0 NEAR)── worker agents
                                   │  ▲
                      reveal_bid ──┘  └── finalize_auction
                                   │
                          NEP-297 EVENT_JSON logs
                                   │
                            indexer (JSON-RPC → SQLite)
                                   │
                    ┌──────────────┴───────────────┐
              REST /tape, /tape/median        React terminal
              /tape/spread, /tape/win-rate    (live data only)
```

## Why Vickrey for AI labor

In a reverse Vickrey auction the lowest bidder wins but is paid the second-lowest price. Bidding your true marginal inference/compute cost is a dominant strategy, so the winning bid is an honest signal and the spread between the winning and runner-up bid is a measurable competitiveness metric. First-price mode remains available for buyers who need a fixed budget outcome. The Tape records both the winning bid and the clearing price, so the Vickrey premium is visible rather than hidden.

## Quickstart

Prerequisites: Node.js ≥ 22.5 (uses `node:sqlite`), Rust 1.86 with the `wasm32-unknown-unknown` target, `cargo-near`, and the OpenSpec CLI (`npm i -g @fission-ai/openspec`). `near-cli-rs` is optional but convenient for read-only calls.

```bash
git clone <repo-url> tender && cd tender
npm ci
```

### 1. Contract tests

```bash
# 5 unit tests + adversarial near-sandbox suite (downloads sandbox on first run)
cargo test --manifest-path contracts/tender/Cargo.toml
```

### 2. Build the contract WASM

```bash
cd contracts/tender
cargo near build non-reproducible-wasm   # -> target/near/tender.wasm
```

If `cargo-near` is unavailable, `cargo build --target wasm32-unknown-unknown --release` also produces a valid artifact. The audited deployment used `cargo-near 0.23.0` and Rust 1.86.0; newer `near-sdk` protocol versions may require a newer toolchain.

### 3. Indexer tests and API

```bash
npm run indexer:test
NEAR_RPC_URL=https://near-testnet.drpc.org \
TENDER_CONTRACTS=tender-hack-1114g.testnet \
npm --prefix packages/indexer start
```

The API listens on `127.0.0.1:8787` by default. For a historical window, also set `TENDER_START_BLOCK` and `TENDER_END_BLOCK`; the live demo leaves the end block open and follows the chain head.

npm --prefix packages/web run dev

## Security model

**Sealed bids.** A commitment is `sha256("tender:v1:<contract>:<job>:<worker>:<bid_yocto>:<eta_seconds>:<salt>")`. Binding contract, job, and worker into the preimage defeats copied commitments, cross-job replay, and cross-deployment replay. Tests cover each case, plus wrong-phase calls, reserve violations, and exact-tie ordering by `commit_seq`.

**Escrow.** NEAR escrow is the production path demonstrated end to end. The contract computes storage cost with `env::storage_byte_cost()`, reserves bounded per-bid slots, and refunds unused storage. NEP-141 escrow is implemented but explicitly experimental (see limitations).

**Payout safety.** Settlement and refunds move through `Settling` / `Refunding` locks. A `#[private]` callback commits the final price only after the transfer succeeds; a failed NEAR or FT payout rolls the job back to a retryable state instead of double-paying or freezing escrow. Dispute payouts pass an override so an arbiter retry can never compound a haircut.

**Disputes.** A buyer can freeze a delivered job for an arbiter review. If the arbiter never acts, anyone may settle at the original clearing price after `dispute_window_ns` (`dispute_timeout_auto_settled`), so neither party can deadlock escrow indefinitely.

### Known limitations (deliberately documented)

- **Worker bonds are reveal-liveness collateral, not performance bonds.** The bond unlocks on a valid reveal and is slashed for non-reveal. A winner who fails to deliver refunds the buyer's escrow but does not lose the bond. A production system should hold the winning bond until settlement.
- **FT escrow is permissionless and experimental.** Any contract can call `ft_on_transfer`, so a fake token can create unbacked FT-denominated jobs. The primary UI filters the Tape, median, spread, and win-rate queries to native NEAR escrow (`escrow=near`) so an experimental token cannot pollute the headline index; FT Vickrey surplus refunds are fire-and-forget and may remain in the contract if the receiver is not registered on the token.
- **Deliverable hashes are anchors, not proofs of correctness.** The contract proves what was delivered and when; judging quality remains a buyer/arbiter responsibility.
- **Arbiters are trusted addresses.** The contract enforces who may resolve and when, not how they judge.
- **The indexer trusts the configured RPC endpoint.** It verifies receipt structure and deduplicates by receipt/log index, but a malicious RPC could omit events. Point it at your own node for stronger guarantees.
- **No mainnet deployment, no real funds, no audit.** This is hackathon software.

## Design deviations from naive NEAR integrations

Each deviation was forced by the protocol, verified against official documentation, and is covered by tests.

1. **Worker calls attach zero NEAR because `FunctionCall` access keys cannot attach a deposit.** A restricted key only carries a gas allowance; the runtime rejects transactions with `attached_deposit > 0`. Therefore `commit_bid`, `reveal_bid`, `submit_delivery`, and `finalize_after_timeout` are non-payable. Bonds live in a pre-funded internal vault (`deposit_bond` / `withdraw_bond`) rather than being attached to each bid. The demo proves the full worker lifecycle with a restricted key. See [NEAR Access Keys](https://docs.near.org/protocol/access-keys).
2. **NEP-141 transfers attach `1 yoctoNEAR` and require receiver storage registration.** `ft_transfer` requires exactly `1 yoctoNEAR` as a user-security confirmation, and it fails if the recipient has not registered with the token contract. The escrow contract attaches that yocto itself and rolls back via a `#[private]` callback on failure. See [NEAR Fungible Tokens](https://docs.near.org/primitives/ft) and [NEP-141](https://github.com/near/NEPs/blob/master/neps/nep-0141.md).
3. **Storage is staked at `10^19 yoctoNEAR/byte`; the `770` free bytes do not apply to contract state.** The free allowance applies only to a bare account record. `create_job` measures the actual storage delta and charges `env::storage_byte_cost()` for the job plus bounded commit/reveal slots; the FT path measures its delta and rejects under-funded credits. See [NEAR Storage Staking](https://docs.near.org/protocol/storage/storage-staking).
4. **Self-reported worker output length was replaced with buyer-declared `work_units` + `unit_label`.** A contract only sees the execution environment — predecessor, attached deposit, block timestamp, and hashes — not the off-chain artifact, so a worker's claimed token count is unverifiable and a per-unit index would reward padding. Buyers declare the unit of work and anchor the spec; workers anchor the deliverable; The Tape computes unit price from those objective fields. See [NEAR Environment](https://docs.near.org/smart-contracts/anatomy/environment).
5. **Payouts are asynchronous and can fail after the initiating receipt succeeds.** Cross-contract promises can fail (deleted receiver, unregistered FT recipient), so settlement cannot assume success. Tender uses in-flight locks and `#[private]` rollback callbacks instead of optimistic balance updates. See [NEAR cross-contract calls](https://docs.near.org/smart-contracts/anatomy/crosscontract).
6. **Dispute resolution has a permissionless liveness fallback.** A trusted arbiter can otherwise freeze escrow forever. After `dispute_window_ns` from the dispute, anyone may settle at the original clearing price, and the phase becomes `DisputeResolutionExpired`.
