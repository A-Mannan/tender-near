# AGENTS.md

Tender is a testnet-only NEAR hackathon project: a Rust sealed-bid clearinghouse contract, a TypeScript indexer/API, and a React market terminal. Do not imply mainnet readiness or real-funds safety.

## Setup and full verification

- Node.js >= 22.5 is required (`node:sqlite`); Rust 1.86 is pinned by `rust-toolchain.toml`. Install with `npm ci` at the repo root.
- Run `scripts/clean-clone-verify.sh /tmp/opencode/tender-clean-verify-final` for the full gate: clean clone, strict OpenSpec, contract unit/sandbox tests, WASM build, indexer tests, web build, testnet read-only call, and Playwright.
- That script clones the local repository, so uncommitted changes and `.data/` are absent. Commit first when using it as proof.
- There is no lint script or CI. `npm --prefix packages/web run build` performs the TypeScript check. `openspec validate tender-mvp --strict` is required after changing OpenSpec artifacts.

## Focused commands

```bash
# Indexer: builds first, then runs all tests from dist
npm run indexer:test
npm --prefix packages/indexer run build
node --test packages/indexer/dist/test/api.test.js
node --test --test-name-pattern='win rate' packages/indexer/dist/test/api.test.js

# Web/UI
npm --prefix packages/web run build
npm --prefix packages/web run dev

# Playwright (after indexer and web builds)
cd packages/web && npx playwright test
cd packages/web && npx playwright test e2e/market.spec.ts --project=desktop

# Contract
cargo test --manifest-path contracts/tender/Cargo.toml
cargo test --manifest-path contracts/tender/Cargo.toml --test clearinghouse_sandbox
```

## Build and test gotchas

- The indexer executes compiled `packages/indexer/dist`, not `src`. Rebuild after every indexer source change before running the API or Playwright.
- Playwright previews the already-built `packages/web/dist`; it does not run a dev server. Build the web app first.
- Playwright defaults to ports `8787`/`4174` and refuses reuse. Override both with `TENDER_E2E_INDEXER_PORT` and `TENDER_E2E_WEB_PORT` when a local server is running.
- The default market suite seeds a fresh DB from `deployments/testnet-replay.json`; it is deterministic and needs no keys or live RPC. It still runs the real projection/API/UI code.
- `TENDER_E2E_LIFECYCLE=1` enables the skipped live testnet lifecycle test. It needs disposable keys in `.data/`, a build with `VITE_TENDER_ENABLE_LOCAL_SIGNER=1`, and performs real testnet writes. Never use production keys.
- Contract sandbox tests download/start `near-sandbox`; first runs are slow. `node:sqlite` ExperimentalWarnings are expected.
- Dependency changes belong in the root lockfile: install from the repo root/workspaces, not inside a package, or clean-clone `npm ci` can fail.

## Architecture and invariants

- `contracts/tender/src/lib.rs`: escrow, commit/reveal, Vickrey/first-price clearing, bonds, disputes, timeout settlement, callbacks, NEP-297 events.
- `packages/indexer/src/index.ts` starts the API and poller. `db.applyBlock()` stores raw events and rebuilds affected jobs/prints; `derive.ts` is the projection logic.
- SQLite schema is inline in `packages/indexer/src/db.ts`; there is no migration framework. `--rebuild` only rebuilds projections from stored events.
- `lastProcessedHeight()` is `MAX(blocks.height)`, not the highest contiguous block. If prints are missing after RPC failures, inspect the `blocks` table for gaps rather than assuming indexing is complete.
- Prices are integer yocto strings. Keep exact `bigint`/decimal-string arithmetic through aggregation and formatting; never coerce yocto amounts to JS numbers.
- NEAR and FT amounts are different denominations. The headline UI intentionally sends `escrow=near`; FT escrow is experimental and must never be aggregated into NEAR metrics. Win-rate filters must apply consistently to both reveals and wins.
- Vickrey clears at `min(runner_up_bid, reserve_price)` when there is a runner-up, and at the winning bid for a single reveal. FirstPrice clears at the winning bid. Ties use earliest `commit_seq`.
- `packages/web/src/hooks/useMarketData.ts` owns the live API reads; `src/lib/api.ts` owns browser API/auth config. `VITE_*` values are baked at build time, so rebuild after changing them.
- `packages/web/public/SKILL.md` is the testnet agent-buyer/worker runbook, served at `/SKILL.md`; `llms.txt` and HTML alternate links advertise it. Discovery is polling-based through `/jobs`, not a registry or push service. Keep buyer deposit authority distinct from zero-attachment worker FunctionCall keys.
- `deployments/testnet.json` is generated by `scripts/verify-testnet.mjs`; do not hand-edit it. `deployments/testnet-replay.json` is the public on-chain window used by browser tests; only update it from verified receipts, and update the strict count/projection tests deliberately.
- `scripts/testnet-demo.mjs` creates jobs and signs transactions on NEAR testnet. Treat it as an explicit human-authorized action.

## Secrets and human-only artifacts

- Never commit `.data/`, `*.sqlite*`, `.env*`, `submission-payload.json`, `*.pem`, `*credentials*.json`, or `.near-credentials/`.
- `.data/testnet-keys*.json` contains disposable testnet private keys. Do not print, copy, or expose them.
- Submission, public repository creation, X posting, and video upload are human-only steps. Do not perform them automatically.
- `README.md` is the user-facing command/proof reference; `openspec/changes/tender-mvp/` is the implementation spec; `progress.md` records historical verification and known findings.
